# المرحلة 5: كتابة وثيقة العقد `api-contract.md`

المرجع: `platform_plan.md`. تُكتب بعد اكتمال المراحل 1 إلى 4.

**الهدف:** مرجع واحد دقيق يقرأه وكيل التطبيق بدل تخمين شكل الـ API. اكتبه من الكود الفعلي لا من الذاكرة، واختصر.

## محتوى الملف (في جذر المشروع)
1. **عام:** النطاق الرسمي للمنصة، وقاعدة الـ API، وشكل الخطأ، والمصادقة.
2. **طرق الدفع:** `GET /api/payment-methods` (الحقول، أمثلة JSON).
3. **الطلبات:** إنشاء الحجز، الدفع (`PATCH /:id/pay`)، قائمة طلباتي، تفصيل طلب، `check/:courseId`، `checkout-requirements`، قيم `status` ومعانيها، وقواعد التحقق (إيصال مطلوب لمن؟ حد حجم الصورة ونوعها).
4. **الإيصال:** صيغة الرفع (base64 data URL مضغوط أو غيره)، الحد الأقصى، ورسائل الأخطاء.
5. **الإشعارات:** جدول لكل نوع إشعار: الرابط الذي يرجعه، وبيانات FCM المصاحبة (`link`, `groupId`, `lectureId`...)، والشاشة المقابلة في الويب.
6. **الحضور وروابط QR:** صيغة رابط الـ QR، ومدة صلاحية الكود، وكيف يُسجَّل الحضور بالكود.
7. **إصدار التطبيق:** حقول `GET /api/settings/app-version` (بما فيها `apkDirectUrl` و`forceUpdate`).
8. **الاستبيان وتقييم المحاضر والمقترحات:** مسارات كل منها وأجسام الطلب والرد، وأين تُعرَّف بنود الاستبيان (في الـ API أم في صفحة الويب؟).
9. **App Links:** اسم الحزمة والنطاق الرسمي ومسارات `assetlinks.json`.
10. **طلبات التطبيق للمنصة:** قسم فارغ يضيف إليه وكيل التطبيق طلباته. **اقرأه** عند هذه المرحلة ثم في المراجعة النهائية، ونفّذ ما يوافق عليه صاحب المشروع.

أضف سطراً لكل نقطة جديدة في قسم "API changes for the app" في `AGENTS.md`.

## معايير القبول
كل مسار مذكور موجود ومجرَّب بمثال طلب/رد؛ لا مسار مكتوب من الذاكرة؛ الملف قصير (جداول وأمثلة، بلا شرح مطوّل).
